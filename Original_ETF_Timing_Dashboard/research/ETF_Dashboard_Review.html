ETF Timing Dashboard — Data Integrity Review

A code-level audit of live market-data retrieval, fallback behaviour and score generation, followed by a targeted refactor for resilience, provenance and transparency. The validated Opportunity Score methodology was left unchanged.
Review date: 16 Nov 2026 Scope: dashboard_template.html · ETF_Timing_Dashboard.html 468 offline + 4 live checks passed 20 / 20 structural checks passed

0Executive summary

The main finding: live data retrieval never worked. Three of the six required symbols (^VIX, ^TNX, ^IRX) were stored pre-encoded as %5EVIX and then URL-encoded a second time, producing %255EVIX. Yahoo returns HTTP 404 for those paths (verified empirically). Because the loader used Promise.all(), a single 404 rejected the whole batch, so every Generate Score request silently fell back to the embedded dataset — while the UI offered no way to tell live from stored data.

Two further latent crash bugs were found by running the real application code under a DOM stub: the score-component bars and comparison chart read the wrong object keys (a .toFixed() on undefined), and the loading-state helper erased the success/error message in finally. All are fixed.

1Complete data flow: fetch request → score generation

BEFORE (as reviewed)

  1. User picks a date and clicks Generate Score → generateScore() → setLoading(true).
  2. loadSeriesForDate(date) computes bufferStart = date − 560 calendar days.
  3. Promise.all() fires six fetchMarketHistory(DATA_CONFIG.symbols[k], bufferStart, date) calls.
  4. Each fetcher built yahooBase + encodeURIComponent(symbol). Stored symbols were already encoded (%5EVIX), so caret series became %255EVIX → HTTP 404. SPY/QQQ/TLT succeeded but were discarded.
  5. The first rejection short-circuited Promise.all. The catch block loaded getEmbeddedSeries() for all six symbols whenever the date fell inside 2000-01-03…2026-11-13 → source: 'embedded'. No date ever produced a live score.
  6. calculateIndicators() truncated every series with upTo(series, date), resolved the last SPY trading day (weekend/holiday handling), then computed SPY 200DMA, 50DMA, 252-session high, 12-month momentum (index len-253), drawdown, TLT 126-day MA, VIX, TNX, IRX, curve and month — all with no look-ahead.
  7. validateIndicators() → indicatorsToScoreInput() → computeScore() (unchanged 25/25/25/15/10 caps) → detectSignals() → renderScore().
  8. renderScore() wrote the score circle, component bars, signal groups, audit table and history chart. setLoading(false) then cleared the status message.

AFTER (implemented)

  1. Same entry point; thresholds() now also reads the user-configurable staleness limits from the Audit panel.
  2. loadSeriesForDate() uses Promise.allSettled() over six independent calls. Each symbol resolves on its own merits.
  3. buildQuoteUrls() encodes the raw symbol exactly once (^VIX → %5EVIX). A configured proxy is tried first; Yahoo is always retained as a second candidate. fetchOnce() adds an AbortController timeout.
  4. parseHistoryJSON() validates the JSON shape, rejects chart.error payloads, and requires meta.symbol to match the requested symbol for Yahoo responses. Transient failures retry with exponential backoff (350 / 700 / 1400 ms, capped 4 s).
  5. Per symbol: fulfilled → source:'live' with provider, request URL, verification URL, retrieval timestamp and reported symbol; rejected → embedded series only if embeddedCoversDate(date), otherwise source:'missing'. Overall source is live | partial | embedded | error.
  6. assessDataQuality() resolves each metric's actual observation date, computes lag vs requested date and feed age vs today, raises warnings (stale, mixed dates, unverified symbol, embedded substitution, missing Fed Funds) and computes the confidence score round(100 × liveCount / 6).
  7. Unchanged: calculateIndicators() → validateIndicators(ind, provenance) → indicatorsToScoreInput() → computeScore() → detectSignals(). No scoring rule was altered.
  8. renderScore() additionally calls renderAuditPanel(), renderQualityPanel() and renderTrendSection(); sourceStatusHtml() states the exact live/embedded/missing mix. setLoading(false) no longer overwrites it.
What is and is not fetched. Six series are fetched from Yahoo Finance chart API: SPY, QQQ, ^VIX, TLT, ^TNX, ^IRX. Fed Funds and the FRED 10Y−2Y spread are not fetched — the FRED endpoint was blocked in this environment. The model's macro component uses a yield-based proxy (13W bill direction + TLT trend), and the score's Yield Curve is ^TNX − ^IRX (10Y − 13W). Both facts are now surfaced in the UI rather than hidden.

4Design rationale

ChangeWhy this design
Raw symbols + single encodingEncoding is a transport concern, not a data concern. Storing ^VIX in configuration keeps the symbol human-readable and comparable with meta.symbol; buildQuoteUrls() is the single encoding point, eliminating any possibility of double-encoding.
Promise.allSettled() + per-symbol provenanceMarket data feeds fail independently. Dropping five good series because one 404'd wastes information and hides partial degradation. Each symbol now carries its own source, provider, request URL, verification URL, timestamp and verified symbol, so mixed results are explicit rather than silent.
Coverage-window guardFalling back for a date outside the dataset would score a different day and mislabel it — a subtle form of fabricated data. embeddedCoversDate() makes that path return missing, so validation refuses to score.
Response symbol verificationProxies and CDNs can return cached or wrong-symbol payloads. Requiring meta.symbol to match the request converts a silent data-corruption risk into a loud, attributable failure. Generic proxy array shapes are accepted but flagged symbolVerified:false.
Exponential backoffYahoo rate limits are usually transient. Two retries (350 / 700 ms, capped 4 s) recover most blips without stalling the UI; the delay is capped so a hard outage still resolves quickly.
Two staleness dimensionsLag (observation vs requested date) detects spliced/missing recent bars; feed age (observation vs today) detects a delayed provider. Feed-age checks are gated to "latest" requests so that intentionally historical queries are not falsely flagged — an important false-positive control.
Confidence = liveCount / 6Simple, auditable and directly tied to inputs. Manual values never count as live; derived metrics inherit the weaker of their two parents. Thresholds are user-configurable so the warning sensitivity can be tuned without code changes.
8-row audit panel with verification linksEvery number in the score can be traced to a provider page. Fed Funds is deliberately shown as Not available with a FRED link rather than a proxy value dressed up as the real series. The Yield Curve row is explicitly marked Derived and notes that FRED T10Y2Y is a different definition.
4-vote trend interpretationA single momentum number is noisy. Combining 30-session change, 90-session change, MA30 slope and MA30−MA90 into four bounded votes gives a deterministic, explainable Improving / Stable / Weakening label. All windows are trailing and clamped to the embedded index, so there is no look-ahead.
Separate pure-function layerbuildQuoteUrls, parseHistoryJSON, calculateIndicators, assessDataQuality, movingAverage, scoreTrendStats and scoreHeatmapData have no DOM dependency. The test harness can execute the real shipped code with a DOM stub instead of a reimplementation — so tests validate production logic, not a copy.

7Remaining known limitations

  1. Browser CORS. Direct Yahoo requests from a file:// page are commonly blocked by browser CORS policy. The dashboard handles this cleanly (labelled embedded fallback for in-range dates), and DATA_CONFIG.proxyEndpoint is a ready hook for a serverless/backend proxy — but no proxy is shipped. Node / server contexts work directly, as the --live run demonstrates.
  2. Fed Funds & FRED unavailable. The FRED CSV endpoint is blocked in this environment. No Fed Funds value exists; the row reads "Not available". The macro component uses an IRX/TLT proxy, and the Yield Curve is 10Y−13W, not FRED's 10Y−2Y. The FRED links are cross-checks only.
  3. Unadjusted closes. Both live and embedded series use Yahoo quote.close, not adjclose. Dividends/splits are not adjusted; this is internally consistent but can slightly distort momentum around ex-dividend dates.
  4. Single Yahoo host. Only query1.finance.yahoo.com is used. A production proxy should rotate hosts and handle rate limiting / caching.
  5. Mixed-source scores. When some symbols are live and others embedded, observation dates can differ. The app warns when the span exceeds 3 calendar days, but a score is still produced — treat partial-confidence results as indicative.
  6. Trend analytics lag live data. MAs, momentum, decomposition and the heatmap are computed from the embedded score history ending 2026-11-13. A live score for a newer date has no embedded MA; the marker clamps to the last embedded observation and this is stated in the UI.
  7. Embedded coverage & warm-up. Coverage is 2000-01-03 → 2026-11-13. TLT begins in 2002, and the indicator engine needs 252 SPY + 126 TLT sessions, so scores before ~2003 are unavailable by design.
  8. Sentiment data. AAII, CNN Fear & Greed and CBOE put/call endpoints remain inaccessible; the original research used VIX percentile as the fear proxy. This review did not change the research model.
  9. Retrieval timestamps are client-side. With no backend, timestamps come from the browser clock and cannot be independently verified against the provider.
  10. Heatmap bucketing. Week buckets are calendar-day groups (1–7, 8–14, 15–21, 22–28, 29–31), not ISO weeks; some buckets are sparse.
  11. No re-backtest. This work improved data integrity and observability only. Strategy win rates, sample sizes and statistical conclusions in the original research report are unchanged.
