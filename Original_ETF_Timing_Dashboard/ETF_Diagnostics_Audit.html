Data Authenticity & Diagnostics Audit

Full review of the ETF Timing Dashboard's Generate Score workflow: where it can fail, how to prove whether Yahoo Finance data is genuinely retrieved, and what was added so a non-technical user can see everything without browser Developer Tools.

1. Executive finding

Live retrieval does work in this build. A real-network test on 16 Nov 2026 fetched all six symbols directly from Yahoo Finance — SPY 387 bars, QQQ 387, ^VIX 389, TLT 387, ^TNX 387, ^IRX 387 — every response passed meta.symbol verification, producing a live score of 71 / 100 (Buy) at 100% confidence.

The reported symptom — "Could not generate score" with no explanation — was a visibility problem, not a data problem. The previous code caught every exception and printed a single generic line, while all HTTP status, latency, response bodies and source decisions were only available in the browser console and Network tab.

This release keeps the validated scoring engine untouched and adds a complete diagnostic substrate: every fetch attempt, parse, fallback and render step is written to an on-page log, with raw provider bodies, per-symbol validation, provider health, a 50-entry audit log and a one-glance transparency report.

4. Data authenticity — how to prove it in the UI

Three independent views now answer "is this real live data?" without any developer tooling:

  • Test Live Market Data — tests all six symbols with no score calculation; prints ✅/❌ per symbol with HTTP status, latency and last bar date, plus an overall Live Data Available / Partial Retrieval / Live Data Unavailable verdict.
  • Raw Provider Response Viewer — the first 200 lines of the actual Yahoo JSON, with retrieved symbol, payload size, HTTP status, verification result and timestamp.
  • Final Transparency Report — shown under every score: source type, provider, retrieval timestamp, market date, live/embedded symbol lists, confidence and verification status.

8. How to use

  1. Open ETF_Timing_Dashboard.html. For live data, serve the folder with python -m http.server 8000 — file:// commonly blocks cross-origin fetches.
  2. Open the 🩺 Diagnostics tab and press Test Live Market Data. Check the ✅/❌ grid and overall verdict.
  3. Press Generate Score in Date Explorer. Expand Fetch diagnostics directly under the button for the step-by-step log.
  4. Read the Final Transparency Report card under the score to see live vs embedded sources.
  5. Use Market Data Audit for per-metric provenance and verification links; the Diagnostics tab holds raw responses, validation, health and the audit log.

9. Remaining limitations

  • Browser CORS: from file://, Yahoo requests may be blocked. The app reports this clearly and falls back to labelled embedded data; an optional proxyEndpoint hook exists for a backend proxy.
  • Fed Funds: FRED is unreachable in this environment; the model uses an IRX/TLT proxy. The audit panel states "Not available" and links to FRED rather than inventing a value.
  • Raw response cap: the viewer shows the first 200 lines per symbol; full bodies are not retained.
  • Local storage: health and audit-log history are per-browser and can be cleared by the user or private-mode settings.
  • Health accounting: each retry attempt counts as an attempt, so transient failures may lower the success ratio even when a later retry succeeds.
  • Trend analytics still derive from the embedded score history ending 2026-11-13; markers for newer dates land on the last available embedded observation.
